# FinLite KG — патч p24

**После обновления один раз:** `npm install` (новая зависимость `qrcode`), затем `npx prisma db push`
(новые таблицы `EntryEvent`, `Attachment`; новые поля у `Company`, `JournalEntry`, `CompanyRecord`, `User` —
изменения только добавляющие, данные не трогаются). Потом — переход на миграции, см. ниже.

- **Запрет изменений закрытого периода** («Закрытие месяца» → «Запретить изменения по …»). Проводки с датой
  по эту дату нельзя добавить, изменить или удалить — ни вручную, ни из выписок, ЭСФ, 1С, зарплаты, ОС,
  склада, курсовых, налогов и закрытия (ответ 423 с понятным текстом). Проверка стоит в одном месте —
  в клиенте Prisma (`lib/ledger/guard.ts`, подключён в `lib/db.ts`), поэтому её не обойти ни одним маршрутом,
  включая удаление строки выписки (каскадом удалило бы проводку). Снять запрет или сдвинуть назад может
  только владелец компании и только с причиной.
- **История проводок**: каждое добавление, изменение, удаление — с автором, временем и снимком «до/после»
  (таблица `EntryEvent`). Пишется в той же транзакции, что и изменение: откат не оставляет следов.
  Кнопка «История» у проводки, вкладка «Журнал изменений» на странице «Проверка журнала». У проводки видно,
  кто её ввёл и кто изменил последним. Ручные проводки и остатки теперь можно **изменить** (не только удалить).
- **Защита от одновременной правки** справочников и настроек (учётная политика, контрагенты, калькуляция,
  бюджет, кадры и др.). Сервер возвращает версии прочитанных записей в заголовке `X-FL-Versions`, браузер
  (`components/VersionTracker.tsx`) отправляет их с сохранением; если запись успел сохранить другой
  пользователь или другая вкладка — 409 «Обновите страницу», а не тихая перезапись. Страницы не менялись.
- **Регулярные операции**: в новой проводке — «Повторять каждый месяц». Дальше проводки создаёт ежедневная
  задача (`/api/cron/daily`), в журнале — панель «Регулярные операции» (пауза, удаление, «Провести, что пора»).
  Месяц не задваивается (`sourceRef = rec:<шаблон>:<ГГГГ-ММ>`), закрытые месяцы пропускаются.
- **Документы к проводкам** (📎): фото или PDF до 4 МБ, хранятся в самой базе; фото уменьшаются в браузере.
  Тип файла проверяется по содержимому. «Чек по фото» может прикрепить снимок чека (только если отмечено).
- **ФИФО на складе**: себестоимость проданного считается по формуле из сохранённой учётной политики —
  ФИФО или средняя. Раньше всегда по средней, даже когда политика говорила «ФИФО».
- **Двухфакторный вход** («Мой аккаунт»): приложение-аутентификатор (RFC 6238) + 10 резервных кодов;
  повтор кода не принимается. Администратор может сбросить 2FA пользователю, потерявшему телефон.
- **Установка как приложение** (PWA): иконка на телефоне/компьютере, ярлыки «Новая проводка», «Чек по фото»,
  «Отчётность»; без связи — понятная страница «Нет связи». Данные не кешируются.

### Переход на версионные миграции (вместо `db push`)

`db push` подгоняет базу под схему «на лету» и при несовместимом изменении может удалить столбец с данными.
Один раз, когда база уже совпадает со схемой (после `npx prisma db push`):

```bash
npm run db:baseline        # создаёт prisma/migrations/0_init и отмечает её в базе как применённую
git add prisma/migrations && git commit -m "Базовая миграция"
```

Дальше: изменили `schema.prisma` → `npm run db:migrate -- --name <что_изменили>` локально, коммит, а на сервере
перед выпуском — `npm run db:deploy`. CI сам переключится: если есть `prisma/migrations`, он применяет миграции
и падает, если схема изменена без миграции.
