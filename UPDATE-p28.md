# FinLite KG — патч p28: надёжное обновление научной сводки

## Что изменилось
- **Сбой одного раздела больше не срывает всю сводку.** Каждый раздел (самые цитируемые, книги, по годам,
  журналы, тренды тем и ключевых слов, Центральная Азия) собирается отдельно. Если OpenAlex не ответил
  на один запрос, в этом разделе остаются данные прошлой сводки, остальное обновляется.
- **На странице видно, что не загрузилось и почему** — жёлтая плашка под вкладками области
  («тренды ключевых слов: OpenAlex не ответил за 15 с», «превышен дневной лимит запросов» и т. п.).
- **Кнопка «Обновить сейчас» обновляет области по очереди**, каждую отдельным запросом, и показывает ход
  («Финансы: загружаю… 2 из 2»). Так каждая область укладывается в лимит времени Vercel (60 с).
- **Запросы к OpenAlex идут по 4 одновременно** — область собирается в 3–4 раза быстрее.
- Понятные сообщения при сбое сети, таймауте (15 с) и ответе 429; один повтор при ошибке сети.
- Ежедневная задача (cron) ограничена 40 с на сводку: если не успела область — она обновится в следующий раз,
  прежние данные сохраняются. Перевод названий запускается, только если осталось время.

## Файлы
- lib/science/openalex.ts — fetchScope по разделам, пул запросов, поля errors/updatedAt у области
- lib/science/server.ts — refreshSnapshot(get, { scope, budgetMs, translate }), сообщения openAlexFetch
- app/api/science/refresh/route.ts — параметр ?scope=accounting|finance
- app/science/page.tsx — обновление по областям с ходом, плашка с ошибками разделов
- lib/science/science.test.ts — тесты: сбой разделов, пул, обновление одной области, бюджет времени

Схема базы не меняется — `prisma db push` не нужен.
