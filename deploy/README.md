# FinLite KG на собственном сервере

Установка в сети организации: все данные остаются на её сервере, наружу программа
обращается только к открытым источникам (курсы НБКР, тексты законов, новостные
ленты) — список и как их отключить ниже.

## Что нужно

| | Минимум | Рекомендуется |
|---|---|---|
| Процессор | 2 ядра | 4 ядра |
| Память | 4 ГБ | 8 ГБ |
| Диск | 20 ГБ SSD | 100 ГБ SSD + отдельный диск или сервер для копий |
| ОС | любой Linux x86-64 с Docker 24+ и Docker Compose v2 (Ubuntu 22.04/24.04, Debian 12, Astra Linux, РЕД ОС) | |
| Сеть | порты 80 и 443 для пользователей; исходящий HTTPS к npm и Docker Hub — только на время сборки | |

Программа на сервере: Docker. Всё остальное (Node.js 22, PostgreSQL 16, Caddy) приходит в контейнерах.

## Установка (15 минут)

```bash
git clone <адрес репозитория> finlite && cd finlite/deploy
cp env.example .env
nano .env        # заполнить: FL_SITE_ADDRESS, POSTGRES_PASSWORD, CRON_SECRET, FL_ADMIN_EMAILS
docker compose up -d --build
docker compose ps            # все сервисы — running / healthy
```

Пароли для `.env`: `openssl rand -base64 32` (база) и `openssl rand -hex 32` (секрет задач).

Откройте `https://<FL_SITE_ADDRESS>` и зарегистрируйтесь с адресом из `FL_ADMIN_EMAILS` — эта
учётная запись получает роль администратора. Раздел «Админ» откроется только после того, как
вы включите двухфакторный вход: «Мой аккаунт» → «Двухфакторный вход».

Проверка: `curl -k https://localhost/api/health` → `{"ok":true,"db":"ok",...}`.
В программе: «Админ» → «Система» показывает версию, базу, настройки защиты и внешние подключения.

## Состав

| Сервис | Что делает | Наружу |
|---|---|---|
| `proxy` (Caddy 2) | HTTPS, сжатие, ограничение размера запроса 40 МБ | 80, 443 |
| `app` (FinLite, Next.js 16 / Node.js 22) | приложение; пользователь `node`, без привилегий | нет |
| `db` (PostgreSQL 16) | все данные, включая сканы документов; том `pgdata` | нет, отдельная внутренняя сеть |
| `cron` | плановые задачи: курсы НБКР, напоминания, новые редакции законов | нет |
| `backup` | ежедневная копия базы в `deploy/backups` | нет |

## HTTPS

- **Доменное имя, видимое из интернета** (`FL_SITE_ADDRESS=finlite.example.kg`): Caddy сам получает и продлевает сертификат Let's Encrypt.
- **Внутренняя сеть** (`FL_SITE_ADDRESS=10.0.5.20` или имя в локальном DNS): Caddy выпускает сертификат своим внутренним центром. Чтобы браузеры не предупреждали, установите его корневой сертификат на рабочие места:
  `docker compose cp proxy:/data/caddy/pki/authorities/local/root.crt ./finlite-root.crt` и распространите через групповую политику.
- **Сертификат организации**: положите `cert.pem` и `key.pem` в `deploy/certs/`, раскомментируйте строку `tls` в `deploy/Caddyfile`, `docker compose restart proxy`.

Работа без HTTPS не предусмотрена: cookie сессии передаётся только по защищённому соединению.

## Резервные копии

Каждый день в `BACKUP_AT` (по Бишкеку) — полная копия базы `deploy/backups/finlite-ГГГГММДД-ЧЧММ.dump`,
старше `BACKUP_KEEP_DAYS` удаляются. В копии всё: проводки, документы, сканы, журнал действий, пользователи.

- Копия сейчас: `docker compose exec -T db pg_dump -U finlite -Fc finlite > backups/manual.dump`
- Восстановление: `sh restore.sh backups/finlite-20261116-0230.dump`
- **Копируйте папку `deploy/backups` на другой сервер или носитель** (rsync, сетевое хранилище): копия на том же диске не спасёт при отказе диска.
- Раз в квартал проверяйте восстановление на тестовом сервере.

Каждая компания дополнительно выгружается целиком из программы: «Компании» → «Резервная копия» (файл `.finlite.json.gz`: проводки, выписки, справочники, настройки) и загружается обратно.

## Обновление

```bash
cd finlite && git pull
cd deploy && docker compose up -d --build
```

При запуске приложение приводит схему базы к новой версии (`prisma db push`). Если новая версия
требует удалить столбец или таблицу с данными, запуск остановится с ошибкой и данные не пострадают —
в этом случае сделайте копию и обратитесь к разработчику.

## Журналы

- Приложение: `docker compose logs -f app`; задачи: `docker compose logs -f cron`; копии: `docker compose logs backup`.
- Ошибки сайта и действия пользователей — в программе: «Админ» → «Ошибки» и «Журнал действий»
  (входы с IP-адресом, неудачные попытки, изменения и удаление проводок, выгрузки, доступ к компаниям,
  действия администраторов; выгрузка в CSV). Срок хранения журнала — `FL_AUDIT_DAYS` (по умолчанию 5 лет).

## Внешние подключения

Сервер сам обращается только к:

| Куда | Зачем | Как отключить |
|---|---|---|
| nbkr.kg | официальные курсы валют, раз в сутки | без доступа курсы вводятся вручную |
| cbd.minjust.gov.kg | тексты законов и новые редакции | закрыть доступ на межсетевом экране |
| новостные ленты (RSS, открытые Telegram-каналы) | раздел «Новости» | закрыть доступ |
| api.openalex.org | раздел «Наука» | закрыть доступ |
| api.resend.com, api.telegram.org | почта и бот | не задавать ключи |
| api.anthropic.com | ИИ-категоризация строк выписки | **выключено, пока не задан `ANTHROPIC_API_KEY`** |

Учётные данные компаний наружу не передаются ни в одном из этих подключений, кроме последнего
(назначение платежа нераспознанных строк выписки), которое по умолчанию выключено.
Программа работает и в полностью закрытой сети — без перечисленных разделов.

## Безопасность — кратко

- Пароли: scrypt с солью; блокировка входа после 5 неверных попыток на 15 минут; двухфакторный вход (TOTP, резервные коды).
- Раздел администратора — только с двухфакторным входом (`FL_REQUIRE_ADMIN_2FA=on`); выход по бездействию выключен, при необходимости — `FL_IDLE_MINUTES`.
- Журнал действий связан цепочкой SHA-256: «Админ → Система → Проверить целостность»; отпечаток последней записи раз в сутки — в `docker compose logs app` (строка `[audit-anchor]`).
- Сессии на сервере, cookie `HttpOnly; Secure; SameSite=Lax`, выход на всех устройствах.
- Доступ к компании проверяется на сервере в каждом запросе; чужая компания отвечает «не найдено».
- Заголовки: Content-Security-Policy, HSTS, X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy.
- Защита от CSRF (проверка Origin), ограничение частоты запросов по IP (адрес клиента — от Caddy, `FL_TRUSTED_PROXIES=1`).
- Файлы Excel разбираются в браузере пользователя, на сервер приходят только строки данных.
- База и приложение не видны из сети напрямую; контейнеры без привилегий (`no-new-privileges`, `cap_drop: ALL`).
